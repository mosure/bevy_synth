# burn_segmentation

Segmentation runtime scaffolding, mask utilities, and model artifact contracts
for scene-scale grounding.

This crate owns segmentation-facing APIs and mask data structures. Scene
composition consumes its outputs through grounding evidence instead of calling
model-specific segmentation code directly.

## Status

- `bbox-prompt` is implemented as a deterministic baseline backend for API,
  artifact, and composition tests.
- `sam2` Burn-native WGPU still-image inference is implemented for component
  BurnPack artifacts imported from upstream SAM2.1 checkpoints. Local
  safetensors are accepted as developer import inputs, but prepared CDN/runtime
  roots use `.bpk` component files.
- SAM2.1 Hiera image encoder variants are detected from weight shapes and block
  counts: `tiny`, `small`, `base-plus`, and `large`. `tiny` and `small` have
  local hook/e2e parity evidence in `tmp/runs`; `base-plus` and `large` share
  the same parameterized implementation but still require checkpoint-specific
  hook captures before claiming parity.
- `sam2` and `sam3` are explicit model kinds with import manifests, BurnPack
  component naming, shard manifest discovery, precision/quantization metadata,
  and parity fixture tooling.
- `sam2` Burn-native WGPU supports native CDN/cache bootstrap for component
  BurnPacks under `model/SAM2.1/`. It prefers `.bpk.parts.json` shards,
  assembles the local `.bpk`, and then loads the component BurnPack. Direct local
  safetensors remain a fallback only for developer snapshots.
- `sam3` still fails fast until model-specific hooks and runtime parity are
  implemented.

## SAM2 WGPU Runtime

Run a profiled SAM2.1 tiny bbox-prompt segmentation pass with component
BurnPacks:

```bash
cargo run --release -p burn_segmentation --features backend_wgpu \
  --bin segmentation_sam2_bench -- \
  --model-root tmp/runs/<run_id>/cdn/model/SAM2.1 \
  --image docs/input_chair.jpg \
  --bbox 0.15,0.10,0.85,0.90 \
  --warmup-runs 3 \
  --runs 5
```

Set `profile_stages=true` on `SegmentationRuntimeConfig` to record synchronized
WGPU stage timings via `SegmentationRuntime::last_stage_timings()`.

For apples-to-apples performance checks, compare release Burn/WGPU against the
warm Python sidecar, not against one-shot hook-capture metadata:

```bash
python crates/burn_segmentation/python/sam2_python_bench.py \
  --sam2-root tmp/upstream/segmentation/sam2 \
  --checkpoint tmp/upstream/segmentation/sam2/checkpoints/sam2.1_hiera_tiny.pt \
  --config configs/sam2.1/sam2.1_hiera_t.yaml \
  --image docs/input_chair.jpg \
  --box 0.15,0.10,0.85,0.90 \
  --warmup-runs 3 \
  --runs 5 \
  --device cuda \
  --output tmp/runs/<run_id>/tiny_python_cuda.json
```

The Burn bench synchronizes stage boundaries when profiling is enabled. Python
and Burn stage names are aligned so `encode` includes high-resolution feature
projection, while `decode` is only the mask decoder.

## Artifact Layout

Local upstream/export source snapshots may contain component safetensors:

- `components/image_encoder.safetensors`
- `components/prompt_encoder.safetensors`
- `components/mask_decoder.safetensors`

These are import inputs only. Do not upload safetensor payloads for the web CDN
bundle.

The canonical CDN/runtime BurnPack names are:

- `image_encoder_<precision>[_<quant>].bpk`
- `prompt_encoder_<precision>[_<quant>].bpk`
- `mask_decoder_<precision>[_<quant>].bpk`

For wasm/CDN upload, each `.bpk` may also have a sibling `.bpk.parts.json` and
`.bpk.part-00000.bpk` files generated by the shared BurnPack parting utility.

The import manifest reports expected S3/CDN paths under:

```text
model/SAM2.1/
```

## Import Planning

Convert local upstream component safetensors into component BurnPacks and write
web/CDN shard manifests:

```bash
cargo run -p burn_segmentation --features import --bin segmentation_import -- \
  --hf-root /path/to/upstream/sam \
  --output-dir tmp/runs/<run_id>/cdn/model/SAM2.1 \
  --model sam2 \
  --model-id facebook/sam2.1-hiera-tiny \
  --precision f16 \
  --quantization none \
  --shard-size-mib 64
```

The command writes `segmentation_import_manifest.json` plus component `.bpk`,
`.bpk.parts.json`, and `.bpk.part-*.bpk` files. The CDN file list in the manifest
must not include safetensor payloads.

## Python Parity Fixtures

Python sidecars should emit `SegmentationParityFixture` JSON with
`python_reference` masks and Burn should emit `burn_observed` masks. Validate it
with:

```bash
cargo run -p burn_segmentation --features import --bin segmentation_parity -- \
  --fixture tmp/runs/<run_id>/segmentation_parity_fixture.json \
  --output tmp/runs/<run_id>/segmentation_parity_summary.json
```

The parity gate checks mask IoU, bbox max absolute error, and area relative
error. Defaults are intentionally strict and can be loosened only in the fixture
thresholds with explicit rationale.
